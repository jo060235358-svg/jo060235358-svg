# Сорен Линдквист (Soren Lindqvist)

`Системный программист` • `Движки хранения данных` • `DSP реального времени` • `Стокгольм, Швеция`

Привет. Я занимаюсь проектированием распределенных систем хранения данных со сверхнизкой задержкой и вычислительных аудиодвижков реального времени. Моя повседневная работа связана с системным программированием на Rust и современном C++, организацией бескросс-копийного (zero-copy) ввода-вывода в ядре Linux через io_uring и детерминированными конечными автоматами.

В свободное от профилирования промахов кэша и проектирования журналов упреждающей записи (WAL) время я экспериментирую с модульными аналоговыми синтезаторами, завариваю пуровер из эфиопских зерен или катаюсь на гравийном велосипеде по дорогам Скандинавии.

---

## 🛠️ Области специализации

- **Высокопроизводительные движки хранения**: Архитектура LSM-деревьев, структуры Write-Ahead Log (WAL) и неблокирующие (lock-free) аллокаторы памяти.
- **Ввод-вывод в ядре и сетевые пути**: Построение асинхронных конвейеров на `io_uring`, сетевые стеки в обход ядра и микросекундная наблюдаемость на базе eBPF.
- **Цифровая обработка сигналов (DSP)**: Разработка физических моделей акустики с векторным ускорением SIMD для пространственной локализации звука.
- **Надежность распределенных систем**: Верификация протоколов консенсуса (Raft) и детерминированное тестирование параллелизма.

## 📂 Избранные проекты с открытым исходным кодом

### 1. `aether-db`
> Встраиваемый персистентный движок хранения на базе LSM-дерева на Rust с прямой асинхронной записью через `io_uring`.
- **Ключевые особенности**: Десериализация без копирования, неблокирующая MemTable на скиплистах, лог фиксации только с операциями добавления (append-only).
- **Стек**: Rust, io_uring, Linux AIO, SIMD-упаковка бит
- **Правило проектирования**: Полное отсутствие динамических выделений памяти в куче на критическом пути записи.

### 2. `pulse-dsp`
> Акустический движок физического моделирования реального времени для пространственного синтеза звука и реверберации помещений.
- **Ключевые особенности**: Расчет многоканального волнового уравнения при 96 кГц / 24 бит с задержкой буфера менее 1.8 мс.
- **Стек**: C++20, интринсики AVX-512 / NEON, CMake, PortAudio

### 3. `trace-tap`
> Минималистичный eBPF-зонд для мониторинга переполнения буферов сокетов Linux и очередей ядра TCP.
- **Ключевые особенности**: Сверхнизкие накладные расходы (<0.4% нагрузки на процессор) для высокочастотного трейдинга и стриминга.
- **Стек**: C, eBPF / libbpf, Zig, точки трассировки Linux

### 4. `nord-vibe`
> CLI-утилита синхронизации цветовых палитр, лигатур шрифтов и рабочих пространств между Neovim, Tmux и Alacritty.
- **Стек**: Go, сокеты домена Unix, TOML

## 📈 Инженерные принципы

1. **Корректность важнее ухищрений**: Высокоскоростной код, возвращающий поврежденные данные, бесполезен. Инварианты должны доказываться тестами на основе свойств (Property testing) и фаззингом.
2. **Механическое понимание (Mechanical Sympathy)**: Понимание кэшей процессора, предсказателей переходов, таблиц страниц и пропускной способности памяти обязательно. Железо — это не абстрактный конструкт.
3. **Детерминированное тестирование**: Симуляции конечных автоматов с фиксированным сидом находят состояния гонки быстрее недель слепого продакшн-тестирования.
4. **Минимизация зависимостей**: Каждая внешняя библиотека — это будущий налог на сопровождение. Предпочтение отдается надежным стандартным интерфейсам.
